## Installing & Updating

We recommend you to use the [Theme manager plugin](https://github.com/galadril/domoticz-theme-manager) to install and keep up-to-date the theme.

You can also manually install it, in Domoticz theme directory :

```
cd /home/${USER}/domoticz/www/styles
git clone https://github.com/domoticz/machinon.git machinon
sudo /etc/init.d/domoticz.sh restart
```

To update it:
```
cd /home/${USER}/domoticz/www/styles/machinon
git pull
```

## Checking beta
```
cd domoticz/www/styles
```

## Development vs. release CSS

`custom.css` in this repo `@import`s its CSS one level deep (see the ONE-LEVEL IMPORT RULE
comment at the top of the file): every leaf feature file (`css/buttons.css`, `css/cards.css`,
etc.) is listed directly, never behind an intermediate file that imports further files. Keep
new feature files at that same one level; do not group them behind a new aggregator, since
each extra level of `@import` nesting serializes another network round trip before the
nested files even start downloading.

Source stays split like this because it is what is easiest to develop and review. Releases
should not ship it as-is: 26+ separate CSS requests is real cost on a slow connection.
`scripts/build-dist.sh` flattens the whole `@import` chain into a single file:

```
scripts/build-dist.sh          # writes dist/custom.css (gitignored, build output only)
scripts/build-dist.sh --check  # verifies every @import in the chain resolves; writes nothing
```

The script walks `custom.css`'s imports depth-first in source order, inlines each file's
content (each section headed by a comment naming its source file), and wraps a
media-conditioned import (e.g. `css/sidemenu.css`'s mobile-only load) in the equivalent
`@media { ... }` block so the conditional behavior survives flattening. It exits non-zero
with a clear error if an import target is missing. Never hand-edit `dist/custom.css`; it is
regenerated by the script and is not committed to the repo.

## Cache problems:

A lot of the problems users experience after a Domoticz update are gone when the browsercache and appcache are cleared. There are also quite a number of posts on this forum related to these kind of problems.

To summarize and sorted from little effort to a bit more effort take these steps and check after each step if it address the issues you encounter.

- First, go to Setup / Parameters / Theme and Click on Reset button and Clear Borwser Cache. If not enought, retry with the Reset Theme button.

- Clear browser cache and appcache 
Chrome: chrome://appcache-internals/#
Firefox: https://support.mozilla.org/en-US/kb/storage 

- In www/js look for domoticz.js.gz, if its there remove it, (KEEP domoticz.js !! )
- Use incognito mode using 
Chrome [control] [shift] n
Firefox: [control] [shift] p

- Restart domoticz
- Rename the location of the original installation and install the new version to an empty target directory. Next copy database and scripts from the old location and fire it up.
